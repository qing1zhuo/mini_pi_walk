# Mini Pi Pro Orin 训练后部署流程

本文档主体整理 D:\Mini_Pi\doc 中已有文档明确写出的内容。第 3.4 节单独记录针对当前服务器无 DISPLAY 报错所做的本地最小适配；第 4 节中的具体 `trtexec` 命令补充自用户提供的操作步骤截图。

当前前提：已经使用 Mini Pi 开源强化学习项目完成训练，训练命令中的 run_name 为 smoke_gpu_1024。下面从官方教学文档的“评估训练好的 policy”步骤继续。

## 1. 文档给出的总体流程

~~~text
完成Isaac Gym训练
  -> 运行play.py评估策略，并导出模型和测试视频
  -> 使用policy_torch.pt运行MuJoCo sim2sim
  -> 将play.py导出的ONNX传到Mini Pi Pro Orin
  -> 在Orin上使用trtexec把ONNX转换为TRT
  -> 把TRT模型放入策略目录并修改YAML
  -> 把YAML控制频率从100Hz改为50Hz
  -> 在Initial状态切换到Custom模式
  -> 进入Standby
  -> 启动自定义行走策略
~~~

来源：

- PiReinforcementLearningbaselineTeachingManual.pdf，第5-6页。
- MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第1-4页。
- PiLivelyMachineDeploymentTutorial.pdf，第1、3、5-6页。

## 2. 训练完成后运行 play.py

强化学习教学手册给出的下一步是评估训练好的 policy，并自动导出适合部署的模型。

先安装 ONNX：

~~~bash
pip install onnx
~~~

手册示例：

~~~bash
cd humanoid

python scripts/play.py \
  --task=pai_ppo \
  --run_name v1
~~~

你训练时使用的 run_name 是 smoke_gpu_1024，因此按照手册的参数对应关系，使用：

~~~bash
cd humanoid

python scripts/play.py \
  --task=pai_ppo \
  --run_name smoke_gpu_1024
~~~

教学手册说明，导出的策略位于：

~~~text
logs/Pai_ppo/exported/policies
~~~

手册展示的文件包括：

~~~text
policy.onnx
policy_torch.pt
~~~

说明：

- play.py 用于评估训练好的策略。
- Mini Pi Pro 开发文档描述的 play.py 测试会在 Isaac Gym 中使用 64 个机器人。
- 该测试包含外力干扰。
- 文档描述其测试内容为直行。
- play.py 导出的 .pt 文件供 sim2sim.py 使用。
- play.py 导出的 ONNX 文件用于后续 Orin 部署。

来源：PiReinforcementLearningbaselineTeachingManual.pdf，第5页；MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第1、3页。

### 2.1 play.py 导出测试视频

当前项目的 `humanoid/scripts/play.py` 已内置 MP4 视频导出功能，不需要另外增加录像代码。脚本末尾的开关为：

~~~python
RENDER = True
~~~

保持 `RENDER = True` 时，`play.py` 会创建相机传感器并将画面写入 MP4。当前代码中的录像设置如下：

| 设置 | 当前值 | 代码位置或作用 |
|---|---:|---|
| 视频编码 | `mp4v` | `cv2.VideoWriter_fourcc(*"mp4v")` |
| 分辨率 | `1920 × 1080` | 相机与 `VideoWriter` 均使用该尺寸 |
| 帧率 | `50 FPS` | `cv2.VideoWriter(..., 50.0, ...)` |
| 录制帧数 | `500` | `stop_state_log = 500` |
| 预计时长 | 约 10 秒 | 500 帧 ÷ 50 FPS |

运行训练结果评估时，视频会随 `play.py` 一并导出：

~~~bash
cd /home/jingwei/minipi/Mini_Pi_RL_Baseline/humanoid

python scripts/play.py \
  --task=pai_ppo \
  --run_name=smoke_gpu_1024
~~~

如果服务器没有图形桌面，可以关闭 Isaac Gym 的交互窗口：

~~~bash
python scripts/play.py \
  --task=pai_ppo \
  --run_name=smoke_gpu_1024 \
  --headless
~~~

当前代码在 headless 模式下仍会创建相机传感器，并且 `RENDER = True` 时仍执行逐帧写入。视频输出目录为：

~~~text
/home/jingwei/minipi/Mini_Pi_RL_Baseline/videos/Pai_ppo/
~~~

文件名由运行时间和 `run_name` 组成，扩展名为 `.mp4`。

需要修改视频长度时，调整：

~~~python
stop_state_log = 500
~~~

需要修改分辨率时，必须同时修改相机尺寸和 `VideoWriter` 尺寸，使两者保持一致：

~~~python
camera_properties.width = 1920
camera_properties.height = 1080

video = cv2.VideoWriter(dir, fourcc, 50.0, (1920, 1080))
~~~

如果不需要导出视频，将脚本末尾改为：

~~~python
RENDER = False
~~~

`sim2sim.py` 当前没有视频导出功能；这里描述的是 Isaac Gym 中运行 `play.py` 时的录像功能。

来源：当前项目 `humanoid/scripts/play.py` 和 `humanoid/envs/base/base_task.py` 的代码实现，不来自 doc 目录中的 PDF 文档。

## 3. 使用 MuJoCo 进行 sim2sim

强化学习教学手册给出的命令是：

~~~bash
python scripts/sim2sim.py \
  --load_model /path/to/logs/Pai_ppo/exported/policies/policy_torch.pt
~~~

其中 /path/to 要替换为 logs 上一级文件夹的实际路径。

Mini Pi Pro 开发文档对 play.py 和 sim2sim.py 的区别描述如下：

| 项目 | play.py | sim2sim.py |
|---|---|---|
| 仿真环境 | Isaac Gym | MuJoCo |
| 机器人数量 | 64个 | 1个 |
| 外力干扰 | 有 | 默认无 |
| 控制方式 | 文档描述为直行测试 | 键盘控制 |
| 用途 | 评估并导出策略 | 更直观、可定制地验证策略 |

### 3.1 MuJoCo 只运行几帧

文档记录的现象：

- sim2sim.py 只出现几帧。
- 程序不可用。
- 显卡几乎没有占用。

文档给出的原因和处理：

- 图形渲染绑定到了 CPU。
- 设置环境变量后恢复。

文档没有给出环境变量的具体名称和值，因此本文不自行补写。

### 3.2 键盘需要连续单点

文档记录 sim2sim.py 默认只有单点逻辑，需要持续单点键盘。

文档给出的处理是：

- 在 sim2sim.py 中添加按住逻辑。

文档没有给出具体代码。

### 3.3 默认无法测试抗干扰

文档说明 MuJoCo 中默认没有外力干扰。

文档给出的处理是：

- 在 sim2sim.py 中增加外力逻辑。
- 在脚本中写好外力大小。
- 将不同外力方向绑定到按键。

文档没有给出具体外力数值和代码。

来源：PiReinforcementLearningbaselineTeachingManual.pdf，第5-6页；MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第1页。

### 3.4 无 DISPLAY 服务器上的最小修改

在无桌面环境的服务器上直接运行 sim2sim.py 时，出现：

~~~text
GLFWError: X11: The DISPLAY environment variable is missing
RuntimeError: Could not initialize GLFW
~~~

针对该错误，当前项目仅对 sim2sim.py 做以下最小适配：

- 增加 `--headless` 参数。
- headless 模式不创建 `MujocoViewer`。
- headless 模式跳过 GLFW 初始化、键盘输入、绘图线程和窗口渲染。
- 策略推理、观测构造、步态周期和仿真时长保持原样。

服务器运行命令：

~~~bash
cd /home/jingwei/minipi/Mini_Pi_RL_Baseline/humanoid

python scripts/sim2sim.py \
  --headless \
  --load_model /home/jingwei/minipi/Mini_Pi_RL_Baseline/logs/Pai_ppo/exported/policies/policy_torch.pt
~~~

headless 模式不能使用键盘，因此默认采用代码中 `cmd` 类的速度值。当前 `cmd.vx` 为 `0.`；如果需要固定向前指令，只修改这一行：

~~~python
class cmd:
    vx = 0.5
~~~

本节来自当前报错和项目代码的本地适配记录，不来自 doc 目录中的 PDF 文档。

## 4. 把 ONNX 模型传到 Mini Pi Pro Orin

Mini Pi Pro 开发文档说明：

- Mini Pi Pro 使用 Orin NX。
- Orin NX 不能使用 Mini Pi 策略转换教程中的 RKNN 模型。
- 应使用 play.py 导出的 ONNX 模型。
- 将 ONNX 模型传输到机器人。
- 在机器人上找到 trtexec。
- 可以把 trtexec 加入系统路径，或者使用绝对路径执行。
- 使用 trtexec 完成 ONNX 到 TRT 的转换。
- 最好在机器人上进行转换，以规避版本问题。

因此 Mini Pi Pro 的格式路线是：

~~~text
ONNX -> TRT
~~~

不是：

~~~text
ONNX -> RKNN
~~~

### 4.1 定位 trtexec

在机器人中查找 TensorRT 自带的 `trtexec` 可执行文件：

~~~bash
find /usr -name "trtexec"
~~~

记录命令返回的实际路径。截图中的示例路径是：

~~~text
/usr/src/tensorrt/bin/trtexec
~~~

### 4.2 将 ONNX 转换为 TensorRT

使用上一步找到的 `trtexec` 路径执行：

~~~bash
/usr/src/tensorrt/bin/trtexec \
  --onnx=/home/nvidia/{path to your onnx file}/{your policy name}.onnx \
  --saveEngine=/home/{your save path}/{your policy name}.trt
~~~

执行前必须把大括号中的占位内容替换为实际路径和策略名称：

- `--onnx`：输入 ONNX 模型文件的完整路径。
- `--saveEngine`：输出 TensorRT 引擎文件（`.trt`）的完整路径。

截图同时说明：

- `.rknn` 用于对应的本地部署设备。
- `.trt` 用于 Pi Plus Pro 机器人；本流程中的 Mini Pi Pro Orin 采用 TensorRT 路线。

开发文档说明最好直接在机器人上完成转换，以规避 TensorRT 版本问题。`trtexec` 的实际位置以 `find` 命令在机器人上的输出为准，不应直接假定示例路径一定存在。

来源：MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第3页；用户提供的 ONNX 转 TensorRT 操作步骤截图。

## 5. 模型传输方式

Mini Pi Pro 开发文档记录板载无线网卡实际不可用时，可以：

- 使用 USB 连接手机上网。
- 使用非宽体 USB-A U盘传输文件。

文档同时提醒：

- 机器人只有两个可用 USB-A 接口和一个 HDMI 接口。
- 三个接口距离很近。
- 宽体 USB-A 设备可能无法与 HDMI 同时使用。

Mini Pi Pro 内置完整的带 GUI 的 Ubuntu 系统，可以通过 HDMI 连接显示器进行开发。

来源：MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第2-3页。

## 6. 存放 TRT 策略并修改 YAML

通用真机部署教程说明，在 sim2real_master 下的以下位置可以找到策略目录：

~~~text
install/share/sim2real/policy
~~~

教程截图将策略按动作类别分为：

~~~text
down
motion
up
walk
~~~

行走策略应放在 walk 类别中。

通用教程说明，Mini Pi 行走算法需要：

1. 在相应算法配置 YAML 中声明策略名和算法名。
2. 在下面的配置中选择要验证的算法策略：

~~~text
sim2real_master/install/share/sim2real/config/pi_config/pi_rl_config.yaml
~~~

Mini Pi Pro 开发文档进一步记录：

- 将 TRT 模型放入指定位置后，如果 YAML 提示找不到模型，需要在模型名前加 walk\。
- 这是因为 Pro 实机的寻址逻辑与 Mini Pi 教程存在差异。

文档表达形式：

~~~text
walk\模型名
~~~

来源：PiLivelyMachineDeploymentTutorial.pdf，第1、3页及截图；MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第3页。

## 7. 对齐控制频率

Mini Pi Pro 开发文档记录的现象：

- 自定义策略运行后行动无力。
- 动作不充分。

文档给出的原因：

- YAML 默认控制频率是 100 Hz。
- Mini Pi 行走策略开源项目的控制频率是 50 Hz。

文档给出的处理：

~~~text
将两者控制频率对齐为50Hz
~~~

来源：MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第3页。

## 8. 训练扭矩与 Pro 真机不一致

Mini Pi Pro 开发文档记录：

- 对齐控制频率后，真机行为仍可能与仿真不一致。
- 此时动作幅度正常。
- Pro 关节电机峰值扭矩为 16 N·m。
- 训练使用的 URDF 写的是 21 N·m。
- 虽然训练中进行了扭矩缩放和剪切，剪切上限仍高于 16 N·m。
- 策略可能依赖真机无法输出的扭矩完成动作。

文档建议：

- 增加域随机化，提高策略的现实落地能力。

来源：MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第4页。

## 9. 绊脚和自转问题

Mini Pi Pro 开发文档记录的现象：

- 机器人出现绊脚。
- 无法完成自转任务。

文档给出一种已经验证的方法：

- 在训练中让双脚保持距离。
- 普通运动使用默认奖励区间 15 cm 到 20 cm。
- 低速自转时将奖励区间适当向右平移，例如 18 cm 到 22 cm。

该方法属于训练奖励修改，需要重新训练策略。

来源：MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第4页。

## 10. Standby 抖动或运动振荡

Mini Pi Pro 开发文档记录：

- Standby 状态可能抖动。
- 实际运动中可能抖动或振荡。

文档给出的处理：

- 降低 YAML 中的 action_scale。
- 逐步降低，直到运动正常。

来源：MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第4页。

## 11. 启动机器人程序

通用 Mini Pi 真机部署教程说明，机器人开机后有自启动脚本。修改配置后验证策略时，可以手动关闭自启动程序，或者执行：

~~~bash
pkill -f ros
~~~

然后按照教程启动 Mini Pi：

~~~bash
cd sim2real_master
source ./install/setup.bash
roslaunch sim2real_master joy_control_pi.launch
~~~

需要注意：

- 上述命令来自通用 Mini Pi 真机部署教程。
- Mini Pi Pro Orin 开发文档没有明确给出 Pro 专用 launch 命令。
- 因此本文不推断 Pro 一定使用相同 launch 文件。

来源：PiLivelyMachineDeploymentTutorial.pdf，第5页。

## 13. 切换到自定义策略

Mini Pi Pro 开发文档给出的流程：

1. 将机器人放置在安全环境中。
2. 退出到 Initial 状态。
3. 使用手柄左侧方向键左右切换模式。
4. 切换到 Custom。
5. 同时按下 LT+RT+A 选中 Custom。
6. 同时按下 LT+RT+START。
7. 机器人站起，进入 Standby。
8. 确认机器人站起后没有异常。
9. 同时按下 LT+RT+LB。
10. 机器人开始运行自定义策略。
11. 如果机器人没有动作，检查机器人终端。

运行状态切换：

- 再次按下 LT+RT+LB，机器人返回 Standby。
- 在上述过程中按下 LT+RT+B，机器人退出运行模式并进入 Protected，关节失力。
- 再次按下 LT+RT+B，机器人进入 Initial。
- 终端会显示上述状态，可以连接显示器查看确认。

安全提醒来自产品手册：

- 在平坦、稳固的表面使用机器人。
- 没有防护架和防护绳时，机器人必须保持在视线范围内。
- 与人员、障碍物、复杂地面和水体保持安全距离。
- 不要把手指或物体放入关节处。
- 长时间待机时，应把机器人吊装在防护架上。

来源：MINI_PI_Pro_Orin_行走策略开发文档_马浩洋.pdf，第2-3页；20260325MiniPiProductManualA5.pdf，“安全须知”。

## 15. 按文档执行的最短流程

在你已经完成训练的前提下，文档支持的后续步骤只有：

1. 安装 ONNX。
2. 运行 play.py，评估策略并导出模型；保持 `RENDER = True` 时同时导出测试视频。
3. 使用 policy_torch.pt 运行 sim2sim.py。
4. 有图形环境时在 MuJoCo 中用键盘验证策略；无 DISPLAY 时使用第 3.4 节的最小 headless 适配。
5. 将 ONNX 模型传到 Mini Pi Pro Orin。
6. 在 Orin 上执行 `find /usr -name "trtexec"` 定位工具，再使用 `--onnx` 和 `--saveEngine` 将 ONNX 转换为 TRT。
7. 把 TRT 模型放入 walk 策略位置。
8. 在 YAML 模型名前添加 walk\。
9. 把 YAML 默认 100 Hz 控制频率改成 50 Hz。
10. 将机器人切换到 Custom。
11. 进入 Standby，确认无异常。
12. 使用 LT+RT+LB 启动自定义策略。
13. 若行动无力，先检查 50 Hz。
14. 若行为与仿真不一致，检查文档指出的 16 N·m 与 21 N·m 差异。
15. 若自转绊脚，按文档修改脚间距奖励并重新训练。
16. 若 Standby 抖动，降低 YAML 的 action_scale。
