# Mini Pi Pro Isaac Gym 训练环境与训练流程

本文档记录无头服务器上的 Isaac Gym 环境安装、分阶段训练、模型导出和无头 MuJoCo 准备。

这套训练环境已经实际验证可以运行官方 Isaac Gym baseline：

- 无头服务器，Ubuntu 20.04
- 2 × NVIDIA GeForce RTX 2080 Ti，每张显存 11 GB
- 无管理员权限
- Conda 环境：`pi_env`，Python 3.8
- PyTorch 2.4.1，CUDA Runtime 12.4
- Isaac Gym Preview 4
- 训练工程：`~/minipi/Mini_Pi_RL_Baseline`

CPU PhysX 最小测试和 64 环境 GPU 训练均已通过。服务器上的 `nvidia-smi` 正常，因此不需要安装系统 CUDA Toolkit。特别注意：不要把 `$CONDA_PREFIX/lib` 添加到 `LD_LIBRARY_PATH`；该设置会让 Conda 动态库覆盖系统库，并曾导致训练在 PhysX 初始化后直接段错误。


| 阶段 | 环境数量 | 目标 |
|---|---:|---|
| 环境验证 | 64 | 验证 Isaac Gym、PyTorch、GPU 管线 |
| 基线复现 | 512 | 确认奖励上升、机器人能够站立 |
| 正式训练 | 1024～2048 | 训练前进、横移、自转 |
| 鲁棒性训练 | 512～1024 | 加入摩擦、质量、延迟、外力随机化 |
| 无头 sim2sim | 1 | 使用 MuJoCo/EGL 验证策略 |

2080 Ti 不建议直接从 4096 环境开始。

## 1. 首先检查服务器

```bash
nvidia-smi

nvidia-smi \
  --query-gpu=name,driver_version,memory.total \
  --format=csv
```

要求：

- 能看到 RTX 2080 Ti
- 显存约 11 GB
- 驱动至少 470
- 如果 `nvidia-smi` 失败，必须找管理员处理
- `nvidia-smi` 显示的 CUDA 版本是驱动最高兼容版本，不代表安装了 CUDA Toolkit

检查磁盘：

```bash
df -h ~
```

建议用户目录至少保留 30～50 GB。

## 2. 无管理员权限安装 Miniconda

如果服务器已经有 Conda，跳过本节。

```bash
mkdir -p ~/.local/installers

curl -L \
  https://repo.anaconda.com/miniconda/Miniconda3-py38_25.1.1-2-Linux-x86_64.sh \
  -o ~/.local/installers/miniconda.sh

bash ~/.local/installers/miniconda.sh \
  -b \
  -p ~/.local/miniconda3

source ~/.local/miniconda3/etc/profile.d/conda.sh
conda init bash
```

重新登录 SSH，创建环境：

```bash
conda create -n pi_env python=3.8 -y
conda activate pi_env
```

## 3. 安装 PyTorch

根据 `nvidia-smi` 显示的 CUDA 上限选择。

如果显示 CUDA 12.4 或更高：

```bash
conda install \
  pytorch=2.4.1 \
  torchvision=0.19.1 \
  torchaudio=2.4.1 \
  pytorch-cuda=12.4 \
  -c pytorch -c nvidia -y
```

如果驱动只支持 CUDA 11.8：

```bash
conda install \
  pytorch=2.4.1 \
  torchvision=0.19.1 \
  torchaudio=2.4.1 \
  pytorch-cuda=11.8 \
  -c pytorch -c nvidia -y
```

验证：

```bash
python -c "import torch; print('torch:',torch.__version__); print('cuda:',torch.version.cuda); print('available:',torch.cuda.is_available()); print('gpu:',torch.cuda.get_device_name(0))"
```

最后必须输出：

```text
available: True
gpu: NVIDIA GeForce RTX 2080 Ti
```

不需要、也不要尝试在无管理员权限下安装系统 CUDA Toolkit。

## 4. 安装 Isaac Gym Preview 4

Isaac Gym 需要接受 NVIDIA 许可后手工下载。将压缩包上传到服务器，例如：

```text
~/minipi/downloads/IsaacGym_Preview_4_Package.tar.gz
```

解压并安装：

```bash
mkdir -p ~/minipi
cd ~/minipi

tar -xf downloads/IsaacGym_Preview_4_Package.tar.gz

conda activate pi_env
cd isaacgym/python
python -m pip install -e .
```

验证导入：

```bash
python -c "from isaacgym import gymapi; import torch; print('Isaac Gym import OK'); print(torch.cuda.is_available())"
```

无头服务器不要使用需要弹出窗口的例程作为主要测试，后续直接运行带 `--headless` 的训练脚本。

## 5. 安装 Mini Pi baseline

```bash
cd ~/minipi

git clone --branch release_v1.0.0 https://github.com/HighTorque-Robotics/Mini_Pi_RL_Baseline.git

cd Mini_Pi_RL_Baseline
conda activate pi_env

python -m pip install -e .
python -m pip install "scipy==1.10.1"
```

官方项目会安装：

- NumPy 1.23.5
- MuJoCo 2.3.6
- mujoco-python-viewer
- WandB
- TensorBoard
- OpenCV
- Matplotlib

验证完整依赖：

```bash
python -c "from isaacgym import gymapi; import torch,numpy,mujoco,scipy,wandb; print('all imports OK'); print(torch.cuda.get_device_name(0)); print('mujoco:',mujoco.__version__)"
```

## 6. 配置无头运行

避免 WandB 弹出登录流程：

```bash
export WANDB_MODE=offline
export WANDB_SILENT=true
```

可以把 WandB 变量放进 Conda 环境的激活脚本，但不要设置下面这条路径：

```bash
# 不要执行，也不要写入 ~/.bashrc 或 Conda 激活脚本
export LD_LIBRARY_PATH="$CONDA_PREFIX/lib:${LD_LIBRARY_PATH:-}"
```

本机上设置该变量后，`/bin/bash` 和 `ldd` 会出现 Conda `libtinfo.so.6` 覆盖系统库的警告，Mini Pi 训练则会在以下位置段错误：

```text
Physics Engine: PhysX
Physics Device: cuda:0
GPU Pipeline: enabled
段错误 (核心已转储)
```

新开 SSH 终端，仅执行 `conda activate pi_env`，不修改 `LD_LIBRARY_PATH` 后，CPU 和 GPU 训练均恢复正常。

如果训练脚本仍试图访问显示器：

```bash
unset DISPLAY
```

Isaac Gym 训练命令必须带：

```text
--headless
```

## 7. 分阶段训练

### 第一阶段：64 环境冒烟测试

```bash
cd ~/minipi/Mini_Pi_RL_Baseline/humanoid
conda activate pi_env

python scripts/train.py \
  --task=pai_ppo \
  --run_name=smoke_64 \
  --headless \
  --num_envs=64 \
  --max_iterations=10 \
  --sim_device=cuda:0 \
  --rl_device=cuda:0 \
  --graphics_device_id=-1
```

观察几个 PPO iteration，确认：

- 没有 CUDA/PhysX 错误
- GPU 利用率明显上升
- 显存稳定
- reward 没有出现 `nan`
- checkpoint 能正常写入

另一 SSH 终端监控：

```bash
watch -n 2 nvidia-smi
```

### 第二阶段：512 环境复现基线

```bash
python scripts/train.py \
  --task=pai_ppo \
  --run_name=baseline_512 \
  --headless \
  --num_envs=512 \
  --sim_device=cuda:0 \
  --rl_device=cuda:0 \
  --graphics_device_id=-1
```

先保持官方奖励函数、随机化和 PPO 参数不变。这个阶段的目标是证明官方配置可以学会站立和行走。

### 第三阶段：寻找合理并行度

依次尝试：

```text
512 → 1024 → 2048
```

选择满足以下条件的最大值：

- 不发生 CUDA OOM
- 显存至少留下约 1 GB 余量
- GPU 利用率较高
- PPO 更新时间没有明显恶化
- 系统不会使用大量 swap

不要默认 4096；2080 Ti 的 11 GB 显存通常更适合 1024～2048。

## 8. 训练任务安排

建议先后训练：

1. 仅站立和平衡。
2. 前后行走。
3. 前后 + 左右横移。
4. 加入低速自转。
5. 扩大速度指令范围。
6. 加入域随机化和外力扰动。

为以后上 Mini Pi Pro，训练配置需要提前对齐：

- 策略控制频率：50 Hz
- 实机电机峰值扭矩上限：16 N·m
- 动作输出：12 DOF
- 左右关节顺序保持一致
- PD 参数与实机 YAML 对齐
- `action_scale` 从保守值开始
- 不要让策略依赖超过实机能力的仿真扭矩

域随机化建议覆盖：

- 地面摩擦系数
- 机体和腿部质量
- 质心位置
- 电机强度
- PD 增益
- 控制延迟
- 关节位置/速度噪声
- IMU 噪声
- 随机水平推力

每次只增加一组随机化，避免无法判断训练退化原因。

## 9. 无头 MuJoCo sim2sim

仓库原始 `sim2sim.py` 会创建 GLFW 窗口，因此在无头服务器上仅设置 `--headless` 不够。正式方案应当给它增加真正的无头模式：

- 不创建 `MujocoViewer`
- 不初始化 GLFW
- 直接循环调用 `mujoco.mj_step`
- 保存关节、姿态、速度、扭矩 CSV
- 需要视频时使用 `mujoco.Renderer` + EGL 离屏渲染

运行环境变量：

```bash
export MUJOCO_GL=egl
export PYOPENGL_PLATFORM=egl
```

训练后的流程是：

```bash
# Isaac Gym 评估并导出。必须显式指定训练目录和checkpoint。
python scripts/play.py \
  --task=pai_ppo \
  --run_name=baseline_512 \
  --load_run=<日期时间_baseline_512> \
  --checkpoint=<迭代号>

# 改造后执行无头 MuJoCo 验证
python scripts/sim2sim.py \
  --headless \
  --load_model /绝对路径/policy_torch.pt
```

sim2sim 至少统计：

- 前进、横移和转向速度跟踪误差
- roll/pitch 最大值
- 基座高度
- 摔倒次数
- 关节限位触发
- 扭矩饱和比例
- 左右脚间距
- 外力扰动后的恢复时间

如果服务器有 `tmux`：

```bash
tmux new -s mini_pi
```

## 11. 已验证的故障排查记录

### 现象

`gymtorch` 可以编译并加载，`create_sim` 显示 GPU PhysX 和 GPU pipeline 已启用，但随后立即段错误。切换为 CPU PhysX 后也在相同阶段段错误。

### 排查结果

- 两张 RTX 2080 Ti 均空闲，不是显存不足。
- `CUDA_VISIBLE_DEVICES` 未设置，不是设备重映射问题。
- `graphics_device_id=-1` 后仍会崩溃，不是无头 Vulkan 渲染问题。
- `gym_38.so` 的 `ldd` 检查没有缺失依赖。
- 最小 `gym.create_sim()` CPU 测试可以成功创建和销毁模拟器。
- 在不修改 `LD_LIBRARY_PATH` 的新 SSH 会话中，CPU 和 GPU 训练均能正常运行。

### 结论

当前环境无需降级 PyTorch。故障由运行时动态库路径污染引起，最可靠的启动方式是使用干净的 SSH 会话：

```bash
conda activate pi_env
export WANDB_MODE=offline
cd ~/minipi/Mini_Pi_RL_Baseline/humanoid

python scripts/train.py \
  --task=pai_ppo \
  --run_name=smoke_gpu_1024 \
  --headless \
  --num_envs=1024 \
  --sim_device=cuda:0 \
  --rl_device=cuda:0 \
  --graphics_device_id=-1
```

建议保存当前已验证环境，便于以后复现：

```bash
conda env export --from-history > ~/minipi/pi_env_history.yml
python -m pip freeze > ~/minipi/pi_env_freeze.txt
```
