# Mini Pi Pro RL 五阶段改进与验收方案

本文面向当前 Mini Pi Pro Isaac Gym + PPO 基线，目标是在尽量少改代码的前提下，按风险和改动量逐级改善策略表现。

完整路线只有五个阶段：

```text
阶段 0：建立名义基线
  -> 阶段 1：随机指令、摩擦和推力
  -> 阶段 2：修正并对齐奖励函数
  -> 阶段 3：保持 PPO 与 Actor-Critic 接口，替换网络骨干
  -> 阶段 4：固定最佳网络骨干，更换 RL 算法
```

适用条件：

- 单张 RTX 2080 Ti，11 GB 显存；
- Isaac Gym 无头训练；
- 当前任务 `pai_ppo`；
- Actor 输入 15 帧 × 47 维，即 705 维；
- Critic 输入 219 维；
- 策略输出 12 维关节动作；
- 策略频率 50 Hz。

## 一、五阶段共同规则

1. 每个阶段只改变该阶段指定的变量。
2. 每个正式对照至少运行 3 个固定 seed。
3. 比较实验时使用相同的总 transition 数，而不是只使用相同 iteration 数。
4. 每个阶段同时保留名义评估和压力评估。
5. 不用训练 reward 代替独立任务指标。
6. 前一阶段没有通过门槛，不进入下一阶段。
7. 每个阶段保存配置、Git commit、checkpoint、逐环境指标和失败案例。
8. 奖励函数变更后视为新的训练目标，正式对照必须从头训练，不只比较 warm-start 结果。
9. 阶段 2 通过后，阶段 1 的名义、摩擦和推力评测矩阵必须全部复验。

RTX 2080 Ti 建议：

| 工作 | 环境数 |
| --- | ---: |
| 快速检查 | 64～256 |
| 阶段对照 | 512 |
| 正式训练 | 1024 |
| 吞吐压测 | 1536～2048 |

不建议直接使用 4096 环境。环境数只影响吞吐和每次更新的数据量，不应被当作提升策略能力的手段。

## 二、所有阶段使用同一套指标

### 任务指标

- 完整回合率/超时率；
- `vx`、`vy`、yaw rate MAE；
- heading MAE；
- 指令切换后的恢复时间；
- 各类指令的最差表现，而不只是总平均值。

### 稳定性指标

- base roll/pitch 的 RMS 和最大值；
- base 高度的均值、标准差和最小值；
- 足底水平滑移速度；
- 非足底碰撞次数；
- 推力后的最大姿态偏差和恢复时间。

### 硬件可实现性指标

- 各关节峰值和 P95 力矩；
- 力矩饱和比例；
- 关节角/速度越限次数；
- 动作一阶、二阶差分；
- 足底冲击；
- 推理延迟和完整控制周期。

### 训练健康度

- policy loss、value loss；
- entropy/action std；
- approximate KL；
- clip fraction；
- explained variance；
- gradient norm；
- 单位 transition 的性能提升。

## 阶段 0：建立可信的名义基线

### 目的

回答两个问题：

1. 当前模型在没有扰动时到底能完成哪些动作？
2. 当前表现差是基础能力不足，还是随机化造成的退化？

已有评估同时打开了摩擦、质量、观测噪声、动作延迟和推力，不能直接作为名义能力基线。现有结果只能说明压力条件下：

- `0.6 m/s` 前进完整回合率约为 29.7%；
- 左右横移的 `vy_mae` 接近指令幅值，几乎没有横移响应；
- 转向能够存活，但 yaw/heading 跟踪较弱。

### 本阶段修改什么

只修改评估配置和日志，不修改训练逻辑：

- 增加名义评估配置：固定摩擦和质量，关闭噪声、延迟和推力；
- 保留当前随机化评估作为组合压力评估；
- 增加逐指令、逐环境指标；
- 增加滑移、姿态、力矩饱和和动作平滑指标；
- 固定一组评估 seed 和指令集合。

如果发现会使比较失效的明确实现错误，例如训练和 sim2sim 的观测周期不一致，应在冻结基线前修正并记录；本阶段不做奖励重构。

### 本阶段保持不变

- 奖励函数及其权重；
- PPO 超参数；
- Actor-Critic 网络；
- 训练指令分布；
- domain randomization 配置。

### 测什么

名义条件下分别测试：

| 类别 | 指令 |
| --- | --- |
| 站立 | `vx=0, vy=0, yaw=0` |
| 前进 | `vx=0.3、0.6 m/s` |
| 后退 | `vx=-0.3 m/s` |
| 横移 | `vy=±0.3 m/s` |
| 原地转向 | 左转、右转、掉头 |
| 组合 | `vx=0.3 m/s` 加左右转向 |

同一 checkpoint 再分别打开单项扰动：

- 仅摩擦变化；
- 仅推力；
- 仅观测噪声；
- 仅动作延迟；
- 最后运行组合压力评估。

### 进入阶段 1 的条件

- 同一 checkpoint、同一 seed 的结果可重复；
- 名义评估和压力评估完全分开；
- 每个动作类别都有独立结果；
- 可以明确指出性能下降来自哪个指令或哪种扰动；
- 形成当前 PPO + MLP 的固定基线报告。

### 本阶段产物

- 名义基线报告；
- 单因素压力报告；
- 组合压力报告；
- 当前 checkpoint 与配置快照；
- 后续阶段不能改变的固定评估集合。

## 阶段 1：递进式随机化

### 目的

在不修改 PPO 和网络结构的情况下，通过更合理的指令覆盖和环境扰动提高策略能力及鲁棒性。

当前仓库已经包含：

- 摩擦随机化 `[0.1, 2.0]`；
- 底座质量随机化；
- 每 4 秒随机推力；
- 观测噪声；
- 动作噪声和动作延迟；
- 随机线速度和目标朝向指令。

因此本阶段不是继续添加更多随机项，而是按“随机指令 → 摩擦 → 推力”的顺序组织现有能力。

### 阶段 1A：随机指令

#### 修改什么

- 将连续均匀采样改为分类型采样；
- 显式控制站立、前后、横移和转向的样本比例；
- 先使用有限速度档位，再逐步加入连续随机值；
- 检查并降低当前 `0.2 m/s` 的速度死区，否则低速指令会被清零；
- 让左右、前后和正负转向采样保持对称。

建议初始分布：

| 指令类型 | 比例 |
| --- | ---: |
| 站立 | 15% |
| 前进/后退 | 35% |
| 原地转向 | 15% |
| 前进加转向 | 20% |
| 横移 | 15% |

#### 保持不变

- 摩擦固定；
- 推力关闭；
- 观测和动作噪声关闭；
- PPO 和网络不变；
- 奖励权重不变。

#### 测什么

- 所有名义指令；
- 左右和前后对称性；
- 训练速度档位之间的插值指令；
- 每 2、4、8 秒切换指令；
- 站立到运动、运动到站立及反向切换。

#### 通过条件

- 每种指令都出现真实响应；
- 横移 `vy_mae` 不再接近指令本身；
- 各动作完整回合率均达到可接受水平；
- 不允许平均值掩盖某一类动作完全失效；
- 3 个 seed 的改善方向一致。

### 阶段 1B：摩擦随机化

#### 修改什么

从固定摩擦逐步扩大范围，而不是直接使用 `[0.1, 2.0]`：

```text
固定 0.6
  -> [0.5, 0.8]
  -> [0.4, 1.0]
  -> 根据真机地面测量决定是否继续扩大
```

#### 保持不变

- 使用阶段 1A 的指令分布；
- 推力仍关闭；
- PPO、网络和奖励不变；
- 其他噪声不增加。

#### 测什么

- 使用固定摩擦网格扫描，而不是只从训练分布抽样；
- 各摩擦值下的完整回合率；
- 速度 MAE；
- 足底水平滑移；
- 姿态变化；
- 名义摩擦 `0.6` 下的性能回归。

#### 通过条件

- 名义性能下降不超过约 5%～10%；
- 训练摩擦范围内没有突然崩溃点；
- 低摩擦环境中的滑移和摔倒明显减少；
- 性能随摩擦变化平滑下降。

### 阶段 1C：随机推力

#### 修改什么

保持当前推力实现时，按强度和频率逐级增加：

```text
无推力
  -> 小推力、低频率
  -> 小推力、高频率
  -> 中等推力、随机方向和随机间隔
```

当前实现通过改写 base 速度模拟冲击，不等同于真实外力。为了控制修改量，本阶段可以继续使用，但必须在报告中明确这一点。

#### 保持不变

- 使用阶段 1A 的指令分布；
- 使用已经通过的摩擦范围；
- PPO、网络和奖励不变；
- 不同时增加质量、传感器和动作噪声。

#### 测什么

- 前后、左右及旋转方向的扰动；
- 推力后的最大 roll/pitch；
- 恢复到目标速度所需时间；
- 推力后的摔倒率；
- 力矩饱和和动作跳变；
- 无推力名义性能是否退化。

#### 通过条件

- 相同推力下恢复时间缩短；
- 推力后的完整回合率提高；
- 名义性能下降不超过约 10%；
- 策略没有通过持续高力矩和僵硬姿态换取抗推能力；
- 3 个 seed 均获得鲁棒性提升。

### 阶段 1 总验收

只有满足以下条件才进入奖励修改实验：

- 名义条件下，各主要动作都已学会；
- 指令覆盖、摩擦鲁棒性和推力恢复均有明确改善；
- 当前 MLP 在多个 seed 下出现稳定、可重复的性能上限；
- 已保存阶段 1 的指令分布、随机化配置、checkpoint 和完整评测结果；
- 后续奖励对照使用阶段 1 完全相同的环境、指令和随机化配置。

## 阶段 2：奖励正确性与任务目标对齐

### 目的

在不修改 PPO、Actor-Critic 网络和阶段 1 环境配置的前提下，解决奖励实现错误、奖励与任务指标不一致，以及固定步态塑形对站立、后退、横移和转向的限制。

本阶段不以“训练总 reward 更高”为成功标准。成功标准是独立任务指标改善，同时稳定性和硬件可实现性不退化。

### 为什么需要单独成阶段

当前奖励存在以下高优先级风险：

- `_neg_sqrd_exp()` 的注释是 `exp(-(x/a)^2)`，实现却额外除以一次 `a`；当 `a=0.1` 时跟踪奖励会变得异常狭；
- `_reward_foot_slip()` 使用刚体状态 `10:12`，实际取到的是角速度而不是足底 x/y 线速度；
- `feet_height` 和 `last_feet_z` 是有状态的奖励缓冲，需确认每个环境重置时正确清零；
- x/y 跟踪奖励分轴计算后取平均，可能在只完成一个方向时仍获得部分高奖励；
- 固定 0.4 s 参考步态及 `feet_clearance`、`feet_contact_number`、`joint_pos` 等奖励与指令无关，可能鼓励所有任务复用单一周期步态；
- 髋/ankle roll 和 thigh yaw 接近零的姿态奖励，可能与横移和转向所需动作直接竞争；
- `only_positive_rewards=True` 会改变负奖励的实际作用，终止惩罚经策略 `dt` 缩放后也需要检查量级。

这些问题同时改动会无法归因，因此必须按下述顺序进行。

### 阶段 2A：奖励正确性修复

#### 修改什么

- 明确 `tracking_sigma_lin/ang` 的数学定义，使 `_neg_sqrd_exp()` 的代码、注释和配置含义一致；
- 将足底滑移改为接触时足部刚体 x/y 线速度，不再使用角速度代替；
- 在环境重置时同步重置 `feet_height`、`last_feet_z` 及其他奖励内部状态；
- 检查每个奖励项的符号、单位、理论范围、`dt` 缩放和终止时序；
- 增加奖励函数级测试，验证误差增大时跟踪奖励单调下降，滑移和能耗增大时惩罚单调增大。

#### 保持不变

- 除了修复实现错误，不调整各项权重；
- PPO、Actor-Critic 网络、观测和动作接口不变；
- 阶段 1 的指令分布、摩擦范围和推力配置不变；
- 训练 transition 预算和评测 seed 不变。

### 阶段 2B：跟踪目标对齐

#### 修改顺序

1. 将 x、y、yaw 跟踪奖励分开记录，先不改权重；
2. 对比“分轴平均”与“平面速度误差范数”两种线速度跟踪形式；
3. 使用宽到窄的 tracking kernel 课程，避免早期误差较大时奖励几乎为零；
4. 只在独立任务指标表明有必要时，再调整 x、y、yaw 权重。

跟踪奖励更改后，必须分别检查站立、前进、后退、横移、原地转向和组合指令，不允许用一类指令的提升掩盖另一类退化。

### 阶段 2C：指令条件化的步态与姿态塑形

#### 修改原则

- 站立指令下关闭或大幅降低周期足部离地、摆动相和参考关节奖励；
- 根据指令速度幅值连续缩放 `feet_clearance`、`feet_air_time`、`feet_contact_number` 和 `joint_pos`；
- 横移时放宽与重心转移相关的 hip/ankle roll 零位约束；
- 转向时放宽 thigh yaw 接近零的约束；
- 优先使用连续 gating，避免奖励在指令阈值附近突变；
- 不同时调整跟踪奖励、步态奖励和硬件代价的权重。

### 阶段 2D：硬件代价复核

在 2A～2C 已经提高任务能力后，再复核：

- 力矩平方和力矩饱和；
- 关节速度和加速度；
- 动作一阶、二阶差分；
- 足底滑移和接触冲击；
- 关节位置、速度和力矩越限。

只在真实物理量指标恶化时调整相应代价。不根据某个负奖励的绝对值直接推断硬件风险。

### 实验组织

正式消融顺序为：

```text
R0：阶段 1 原奖励基线
  -> R1：只修复奖励实现错误
  -> R2：跟踪函数与 kernel
  -> R3：指令条件化步态/姿态奖励
  -> R4：硬件代价微调
```

每个正式对照均应：

- 从随机初始化从头训练，使用至少 3 个固定 seed；
- 使用相同总 transition 数；
- 保持阶段 1 的指令、摩擦和推力配置；
- 同时执行名义、单因素和组合压力评测；
- 记录每个奖励项的原始值、加权值、占比和裁剪前后总值；
- warm-start 只用于快速筛选，不作为正式结论。

### 本阶段保持不变

- PPO 损失、超参数和更新方式；
- Actor-Critic 网络结构和初始化方式；
- Actor/Critic 观测、动作空间和控制器；
- 阶段 1 确定的指令分布和重采样周期；
- 阶段 1 确定的摩擦、推力和其他 domain randomization；
- 总 transition 预算、训练 seed 和评测 seed。

### 进入阶段 3 的条件

新奖励至少满足：

- 站立漂移、后退、横移或转向中的主要短板在多 seed 下明确改善；
- 每一类指令都产生真实响应，不存在通过固定前进步态获取高奖励的情况；
- 名义完整回合率下降不超过约 5 个百分点；
- 阶段 1 摩擦和推力评测中没有明显退化；
- roll/pitch、滑移、P95 力矩、饱和比例和动作差分不恶化超过预先设定的容差；
- 3 个 seed 的改善方向一致，且最差 seed 不劣于原奖励基线；
- reward 提升与独立任务指标改善一致，未出现 reward hacking。

如果新奖励只改善训练 reward，或以牺牲稳定性、力矩和动作平滑性为代价，则不通过本阶段。

## 阶段 3：保持 PPO 和 Actor-Critic 接口，替换网络骨干

### 目的

验证当前 15 帧历史观测是否能通过时序网络获得比展平 MLP 更好的表示能力。

“MLP 改为 Transformer”本身属于修改网络骨干。因此本阶段准确含义是：

> 保持 PPO、Runner、RolloutStorage 和 Actor-Critic 外部接口不变，只替换 Actor/或 Critic 内部的编码网络。

### 修改顺序

按改动量由小到大：

1. 调整 MLP 宽度和深度；
2. 1D temporal convolution/TCN；
3. GRU；
4. 小型 Transformer。

不建议直接跳到大型 Transformer。当前序列只有 15 帧，输入中已经包含步态相位，Transformer 不一定自然优于 MLP。

### 最小 Transformer 结构

为了减少环境和部署改动，外部输入继续保持 705 维：

```text
[B, 705]
  -> reshape [B, 15, 47]
  -> 单帧映射到 d_model=64 或 128
  -> 位置编码
  -> 1～2 层 Transformer Encoder
  -> 最后一帧或时间池化
  -> MLP action head
  -> 12 维动作均值
```

初始实验建议只替换 Actor，Critic 继续使用当前 219 维 MLP。Actor 和 Critic 同时修改会增加归因难度。

### 本阶段保持不变

- PPO 损失与更新逻辑；
- 学习率、epoch、mini-batch、gamma、lambda；
- 阶段 1 确定的指令分布；
- 阶段 1 确定的随机化；
- 阶段 2 通过的奖励函数和权重；
- Actor 外部输入 705 维；
- 动作输出 12 维；
- 总 transition 预算和评估 seed。

### 测什么

#### 能力指标

- 阶段 0 的全部名义指令；
- 阶段 1 的摩擦扫描；
- 阶段 1 的推力测试；
- 指令切换；
- 最差动作类别。

#### 训练指标

- 达到同一门槛需要的 transition 数；
- 3 个 seed 的均值和方差；
- explained variance；
- KL、clip fraction、entropy；
- 是否更容易出现训练崩溃或策略退化。

#### 工程指标

- 2080 Ti 峰值显存；
- 每秒 environment steps；
- PPO update 用时；
- 策略推理延迟；
- TorchScript 导出；
- ONNX 导出；
- Orin TensorRT 转换和 50 Hz 实时性。

### 进入阶段 4 的条件

新网络至少满足：

- 多 seed 下稳定优于原始 MLP；
- 最差指令类别有明确提升，例如超过约 10%；
- 名义和随机化测试均没有明显退化；
- 训练吞吐下降可接受，例如不超过约 20%～30%；
- 部署端完整控制循环满足 50 Hz；
- TorchScript、ONNX 和 TensorRT 路线可用。

如果 Transformer 只提高训练 reward，没有提高独立评估指标，保留 MLP。阶段 4 应使用阶段 3 中综合表现最好的网络，而不是默认使用最复杂的网络。

## 阶段 4：固定最佳网络骨干，更换 RL 算法

### 目的

在环境、随机化和网络表示能力已经固定后，验证其他 RL 优化算法是否比 PPO 更稳定、更高效或性能更高。

### 基本原则

- 固定阶段 3 选出的最佳网络编码器；
- 固定阶段 1 的环境、指令和随机化；
- 固定阶段 2 通过的奖励函数和权重；
- 只改变数据存储、损失和更新算法；
- 不同时更换网络骨干和 RL 算法；
- 使用相同总 transition 数和相同 seed。

当前 `pai_my_ppo` 只是标准 PPO 的复制和改名，没有新的优化目标，不能作为新算法实验结果。

### 算法尝试顺序

#### 4A：PPO 小改型

改动最小，优先尝试：

- PPO 超参数系统搜索；
- recurrent PPO；
- PPO 加 auxiliary loss；
- teacher-student/RMA 式适应模块；
- 对 privileged observation 增加显式编码或估计任务。

这些方法不一定属于完全不同的 RL 算法，但最适合先判断标准 PPO 是否已经被充分利用。

#### 4B：保持 Actor-Critic 形式的替代算法

可以测试 A2C 或 TRPO：

- A2C 改动相对小，但可能比 PPO 更不稳定；
- TRPO 需要更复杂的约束和二阶近似，训练成本更高。

它们适合作为研究对照，不保证优于调好的 PPO。

#### 4C：Off-policy 算法

最后再考虑 SAC 或 TD3。它们需要：

- ReplayBuffer；
- SAC 的双 Q 网络和 target network；
- TD3 的双 Critic、目标策略和延迟更新；
- 新 Runner 和更新频率；
- 新 checkpoint 与恢复逻辑。

当前 705 维历史观测会使 replay 占用较大内存；1024 个并行环境也会快速生成大量数据。需要单独设计 replay 容量、CPU/GPU 存储和 update-to-data ratio。

在大规模并行 Isaac Gym 中，PPO 能快速获得新样本，因此 SAC/TD3 的样本复用优势未必能转化为更短的实际训练时间。

### 本阶段保持不变

- 最佳网络骨干；
- 环境与奖励；
- 指令分布；
- domain randomization；
- 观测和动作接口；
- 总 transition 预算；
- 评估矩阵和 seed。

### 测什么

#### 性能比较

- 相同 transition 数下的学习曲线；
- 相同实际训练时间下的学习曲线；
- 最终名义性能；
- 摩擦和推力鲁棒性；
- 最差指令类别；
- 跨 seed 方差。

#### 稳定性比较

- NaN、策略崩溃和性能回退次数；
- PPO 的 KL/clip 指标或 off-policy 的 Q 值范围；
- Actor/Critic loss；
- 动作熵；
- checkpoint 恢复后的连续性。

#### 工程比较

- 训练墙钟时间；
- GPU 显存和 CPU 内存；
- ReplayBuffer 占用；
- 推理延迟；
- TorchScript、ONNX 和 TensorRT 导出；
- 是否仍保持统一的 `705 -> 12` 部署接口。

### 最终替换 PPO 的条件

新算法应同时满足：

- 相同样本预算下稳定优于 PPO；
- 相同训练时间下仍有优势；
- 至少 3 个 seed 的均值和最差结果都更好；
- 名义性能和随机化性能没有明显短板；
- 工程复杂度与性能收益匹配；
- checkpoint、评估、导出和部署链路可维护。

如果新算法只在单个 seed 或单项指标上更好，不替换 PPO。

## 三、阶段决策表

| 现象 | 当前判断 | 应停留/回退阶段 |
| --- | --- | --- |
| 名义条件下横移仍无响应 | 不是摩擦和推力问题 | 阶段 1A |
| 名义能力正常，摩擦变化就倒 | 需要摩擦随机化 | 阶段 1B |
| 名义和摩擦正常，推力后恢复差 | 需要推力课程 | 阶段 1C |
| 奖励随误差变化不单调或量级异常 | 先修正公式、索引、重置和 `dt` 缩放 | 阶段 2A |
| 总 reward 高，但后退/横移/转向跟踪差 | 奖励与任务指标不对齐 | 阶段 2B/2C |
| 跟踪提升，但力矩、滑移或动作跳变恶化 | 硬件代价不足 | 阶段 2D |
| 新 reward 在名义条件提升，但摩擦/推力退化 | 奖励破坏了阶段 1 鲁棒性 | 阶段 2，回退或重做压力对照 |
| 奖励与环境已固定，MLP 多 seed 稳定达到平台 | 可以比较时序骨干 | 阶段 3 |
| Transformer reward 高但任务指标不高 | 网络没有实际收益 | 回退 MLP/GRU |
| 新骨干性能好但无法部署到 Orin | 工程门槛未通过 | 阶段 3 |
| PPO 不同 seed 差异大 | 先调 PPO/训练稳定性 | 阶段 4A |
| PPO 已稳定但性能仍受限 | 再测试其他算法 | 阶段 4B/4C |
| SAC/TD3 样本效率高但墙钟时间更慢 | 不一定值得替换 | 保留 PPO |

每份 `conclusion.md` 只回答：

1. 本阶段唯一改变的变量是什么；
2. 名义性能和压力性能分别怎样变化；
3. 多 seed 是否一致；
4. 是否达到进入下一阶段的条件；
5. 最终保留哪个配置或模型作为下一阶段基线。

## 五、最终判断

这套五阶段流程可行，风险和改动量逐级增加：

| 阶段 | 改动量 | 预期收益 | 风险 |
| --- | ---: | ---: | ---: |
| 阶段 0：基线评估 | 很小 | 为后续提供可信依据 | 低 |
| 阶段 1：随机化 | 小 | 通常最高 | 低～中 |
| 阶段 2：奖励修正与对齐 | 小～中 | 解决任务短板的潜力高 | 中 |
| 阶段 3：网络骨干 | 中 | 不确定，需要消融 | 中 |
| 阶段 4：RL 算法 | 大 | 不确定 | 高 |

最重要的控制变量是：

- 阶段 1 不改奖励、PPO 和网络；
- 阶段 2 只改奖励，不改环境、网络和 PPO；
- 阶段 3 固定环境、奖励和 PPO，只改网络骨干；
- 阶段 4 固定最佳网络，只改 RL 优化算法。
